## Architecture

An unofficial Go client for the Creditsafe Connect APIs, module `github.com/scriplylabs/goclient-creditsafe`. It is not affiliated with or endorsed by Creditsafe; keep the README disclaimer.

- Root package `creditsafe` holds what every Creditsafe product shares:
  - `client.go`: `Client`, `New` with functional options (`WithCredentials`, `WithToken`, `WithSandbox`, `WithBaseURL`, `WithHTTPClient`), `Do` (the authenticated transport, which satisfies the `HttpRequestDoer` interface generated clients use), `DoJSON` and `NewRequest`.
  - `auth.go`: `POST /authenticate`. Tokens are JWTs and are renewed `renewBefore` (1 minute) ahead of their `exp` claim. A 401 triggers one fresh login and one resend, but only when the request body can be replayed. A mutex makes concurrent callers share a single login.
  - `errors.go`: `*APIError` and the status sentinels.
- Each Creditsafe product has its own generated package, built on a `*creditsafe.Client`: `creditrisk/` (Credit and Risk: company and director search, credit reports, images, fresh investigations) and `kyc/` (KYC Protect). Creditsafe publishes a separate flat spec per product.
- `internal/apicall`: what generated packages share: `CheckingDoer` (turns every non-2xx response into `*creditsafe.APIError` before generated code sees it), `BuildServerURL`, and the `Decode`/`DecodeValue`/`Discard` helpers the template calls.
- `internal/overlaycheck`: `Check`, used by each package's `TestOverlayNamesEveryOperation`.

## Generated code (creditrisk, kyc)

`<pkg>/<pkg>.gen.go` is generated by `scripts/generate.sh` (oapi-codegen, pinned in the script), which regenerates every directory holding an `oapi-codegen.yaml`. Never edit generated files by hand; change an input and regenerate. CI fails if they're stale. Inputs:

- `<pkg>/openapi/*.json`: Creditsafe's spec, unmodified, exactly one per package. To update it, run `scripts/generate.sh <pkg> path/to/new.json`.
- `<pkg>/openapi/overlay.yaml`: the Go name for every operation (an OpenAPI Overlay that rewrites `operationId`); it also removes `/authenticate`. `TestOverlayNamesEveryOperation` fails when a spec operation has no name. Names follow `List/Get/Create/Update/Delete` + resource, with `Search`, `Match`, `Bulk`, `Link` and `Download` where the API uses them, and initialisms like `AML` kept intact.
- `<pkg>/oapi-codegen.yaml`: generator config. It imports `internal/apicall` (`additional-imports`) and points at the shared templates.
- `codegen/templates/client.tmpl`: oapi-codegen's template with the raw client's names unexported. The rename list is in its header; redo it when bumping the version.
- `codegen/templates/client-with-responses.tmpl`: generates the public `Client` methods: `(*T, error)` for a JSON body, `(T, error)` for a JSON array, `(*http.Response, error)` for a non-JSON body (file downloads; the caller closes it), or `error` when there's no body.
- `<pkg>/<pkg>.go` (hand-written): the package doc, `Client` and `New`.

## Required Patterns

- Every method that makes a request takes `context.Context` first.
- Every non-2xx response is an `*APIError` from `CheckResponse`, matched with `errors.Is` against a sentinel. Don't add per-endpoint error types. A new error shape gets a field on `APIError` or `errorBody` instead.
- Creditsafe's error shapes (from the KYC Protect spec, corrected by live calls on 2026-11-03):
  - `{correlationId, message, details}` for 400, 404, 409 and 500. Seen live for 403 too (`"Forbidden"` / `"No access"` when the account lacks the product), though the spec says 403 is `{message}`.
  - `{error}` for an invalid or expired token (401). Confirmed live: `{"error":"Invalid token."}`.
  - `{message}` for a failed login (not yet seen live)
  - RFC 7807 problem details on some endpoints and inside batch partial failures (not yet seen live)
- Tokens are JWTs from `https://mylogin.creditsafe.com`, valid for one hour (confirmed live).
- Wrap a cause with `%w` so it stays matchable. A refused login wraps both `ErrAuthentication` and the `*APIError`.
- The root package uses only the standard library.

## Testing

Unit tests make no live calls. Use `httptest` (see `fakeAPI` in `client_test.go`).

Live tests (`live_test.go` files, build tag `live`) run against production and only read: `go test -tags live -run Live -v ./...`. The account has Credit and Risk access; KYC Protect answers 403 until Creditsafe enables it. They take credentials or a token from the gitignored `.env` (see `.env.example`), and log error fields and counts, never tokens or profile contents. Production calls are kept to a minimum: each package has one live test making one call, and a session confirms changes with a single live call, not a suite. Don't add a live test that creates, changes or deletes data, fetches a report or image, runs a KYC search (these may be billed), or uses a wrong password (may lock the account).
