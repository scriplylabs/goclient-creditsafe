## Architecture

An unofficial Go client for the Creditsafe Connect APIs, module `github.com/scriplylabs/goclient-creditsafe`. It is not affiliated with or endorsed by Creditsafe; keep the README disclaimer.

- Root package `creditsafe` holds what every Creditsafe product shares:
  - `client.go`: `Client`, `New` with functional options (`WithCredentials`, `WithToken`, `WithSandbox`, `WithBaseURL`, `WithHTTPClient`), `Do` (the authenticated transport, which satisfies the `HttpRequestDoer` interface generated clients use), `DoJSON` and `NewRequest`.
  - `auth.go`: `POST /authenticate`. Tokens are JWTs and are renewed `renewBefore` (1 minute) ahead of their `exp` claim. A 401 triggers one fresh login and one resend, but only when the request body can be replayed. A mutex makes concurrent callers share a single login.
  - `errors.go`: `*APIError` and the status sentinels.
- Each Creditsafe product has its own package (`kyc/` for KYC Protect), built on a `*creditsafe.Client`. Creditsafe publishes a separate flat spec per product.

## Generated code (kyc)

`kyc/kyc.gen.go` is generated by `scripts/generate.sh` (oapi-codegen, pinned in the script). Never edit it by hand; change one of its inputs and regenerate. CI fails if it's stale.

- `kyc/openapi/kycProtect.json`: Creditsafe's spec, unmodified. To update it, run `scripts/generate.sh path/to/new.json`.
- `kyc/openapi/overlay.yaml`: the Go name for every operation (an OpenAPI Overlay that rewrites `operationId`), and it removes `/authenticate`. `TestOverlayNamesEveryOperation` fails when a spec operation has no name. Names follow `List/Get/Create/Update/Delete` + resource, with `Bulk`, `Link` and `Download` where the API uses them, and initialisms like `AML` kept intact.
- `kyc/templates/client.tmpl`: oapi-codegen's template with the raw client's names unexported. The rename list is in its header; redo it when bumping the version.
- `kyc/templates/client-with-responses.tmpl`: generates the public `Client` methods. They return `(*T, error)` (or `(T, error)` for slices), or just `error` when there's no 2xx JSON body.
- `kyc/kyc.go` (hand-written): `Client`, `New`, and `checkingDoer`, which turns every non-2xx response into `*creditsafe.APIError` before generated code sees it.

## Required Patterns

- Every method that makes a request takes `context.Context` first.
- Every non-2xx response is an `*APIError` from `CheckResponse`, matched with `errors.Is` against a sentinel. Don't add per-endpoint error types. A new error shape gets a field on `APIError` or `errorBody` instead.
- Creditsafe's error shapes (from the KYC Protect spec):
  - `{correlationId, message, details}` for 400, 404, 409 and 500
  - `{error}` for an invalid or expired token (401)
  - `{message}` for 403 and for a failed login
  - RFC 7807 problem details on some endpoints and inside batch partial failures
- Wrap a cause with `%w` so it stays matchable. A refused login wraps both `ErrAuthentication` and the `*APIError`.
- The root package uses only the standard library.

## Testing

Unit tests make no live calls. Use `httptest` (see `fakeAPI` in `client_test.go`). Sandbox credentials are pending; until they arrive, error bodies come from the spec and aren't confirmed against the real API.
